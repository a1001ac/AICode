摘 要
在当今软件工程领域，人工智能与低代码或零代码开发技术的融合正在重塑软件的生命周期。传统的开发模式高度依赖人工逻辑，面临大量的人力成本以及开发原型验证缓慢等问题。随着大语言模型的不断演进，程序员的开发模式正在从传统的纯手写代码转向基于大语言模型驱动的AI零代码应用生成，即以意图为导向的自动化生成。
本研究设计并实现了一个面向个人或小团队的AI零代码应用生成平台，集成了自动化部署，核心思想在于通过自然语言的驱动，实现从用户需求描述到在线可访问应用的端到端转化。该平台以后端SpringBoot为核心支柱，集成LangChain4J框架来构建智能体驱动的代码生成引擎。系统同时集成了基于Redis的接口限流机制与会话管理、Mybatis-Plus驱动的数据持久化、异步生成应用封面截图并一键部署的整套流水线。前端采用Vue3、TypeScript以及流式渲染技术来构建响应式的交互页面，用户能直观看到代码输出并可实时预览生成的应用。
系统核心创新点在于建立了一套预制Prompt的多类型代码生成路由机制，能够精准识别用户需求然后生成、解析并保存代码，将用户的需求转变为能看到的应用。本系统对开发者来说也能降低开发门槛与开发时间，将应用交付周期缩至分钟级。本文详细探讨了该系统的需求分析、系统架构设计、核心模块实现以及针对代码生成质量与系统稳定性的测试验证，为智能化软件开发工具的研究提供了实践参考。
关键词：软件工程；大语言模型；零代码应用生成；流式渲染；响应式；接口限流
Abstract
In today's software engineering field, the integration of artificial intelligence with low code or zero code development techniques is reshaping the software lifecycle. The traditional development model heavily relies on manual logic and faces issues such as high labor costs and slow prototype validation. With the continuous evolution of big language models, the development mode of programmers is shifting from traditional pure handwritten code to AI zero code application generation driven by big language models, that is, intention oriented automated generation.
This study designed and implemented an AI zero code application generation platform for individuals or small teams, which integrates automated deployment and aims to achieve end-to-end conversion from user requirement description to online accessible applications through natural language driving. The platform uses backend SpringBoot as its core pillar and integrates LangChain4J framework to build an intelligent agent driven code generation engine. The front-end uses Vue3, TypeScript, and streaming rendering technology to build responsive interactive pages, allowing users to visually see the code output and preview the generated application in real-time.
The core innovation of the system lies in the establishment of a pre packaged Prompt multi type code generation routing mechanism, which can accurately identify user needs and generate, parse, and save code. The system integrates Redis based interface flow limiting mechanism and session management, Mybatis Plus driven data persistence, and a complete pipeline for asynchronous generation of application cover screenshots and one click deployment. This system can significantly reduce the development threshold and time for developers, and shorten the application delivery cycle to minutes. This article discusses in detail the requirements analysis, system architecture design, core module implementation, and testing and verification of code generation quality and system stability for the system, providing practical reference for the research of intelligent software development tools.
Keywords: software engineering; Large Language Model (LLM) Zero code application generation; Streaming rendering; Responsive; Rate Limiting

第1章 绪 论
1.1 研究背景及意义
1.1.1 大模型驱动的软件开发变革
软件开发经历了多个阶段的演变。一开始的汇编语言时代，作为开发者需要掌握很深入的专业技术知识，导致从事软件开发行业门槛很高，直到演变出了系统语言，比如C和C++通过提供更强的硬件控制能力，同时降低了编程复杂性，这一演变大大降低了开发者的开发门槛。后来有了Java以及JavaScript，通过虚拟机和自动内存管理提高了开发效率，让开发者不用执着于计算机底层知识，也能开发出想要的应用程序。1989年，荷兰程序员Guido van Rossum在一个圣诞节期间完成了Python的开发，其设计理念强调代码的可读性和间接性，这一演变进一步简化了开发，使编程更加易学易用。整个演变进程令人感到十分惊叹，从最初的打孔式编程到多层次的抽象提升，每一步都在降低开发者的开发门槛。
近几年，随着人工智能的快速发展，互联网上各个大模型厂商堪称百花齐放，各种各样的大语言模型频频涌出。围绕软件开发生命周期，从代码自动化生成到智能化测试，从需求分析到系统运维，AI大模型已经深入融入软件开发的各个环节。这种变革方式不仅改变了开发者的工作方式，也为企业和整个产业链带来了新的机遇以及挑战。
1.1.2 零代码应用生成的发展现状与需求
在数字化转型的今天，全球企业对软件解决方案的需求疯狂增长。传统的软件开发方式因其需要高昂的人力成本、交付周期长已经难以匹配当今市场快速迭代的节奏。在此背景下，低代码与无代码开发平台应运而生。根据最新的行业调查报告，低代码平台市场正处于高速扩张期，预计到2032年全球市场规模将达到264.4亿美元，2024年至2032年间的复合增长率高达32%‎[1]。
与此同时，生成式人工智能的突破为低代码领域注入了前所未有的力量。通过在海量的网络开源代码数据集上进行预训练，大语言模型展现出了非常优秀的代码编写、重构以及逻辑推理能力。很多企业在面对这股低代码浪潮也纷纷选择加入，像字节跳动内部也使用旗下编程助手Trae作为辅助开发方案。因此AI的角色已不再局限于代码补全的辅助工具，而是演变为协同开发者，通过理解用户自然语言并分析意图，自主构建具有高度可靠性和适用性的软件系统。现如今低代码和零代码开发平台已成为加速软件开发的关键，尤其对编码能力有限的个人来说‎[2]。
1.1.3 面向个人/小团队的“零代码应用生成与部署”平台意义
对于一些资源受限的个人开发者或者小团队，快速开发以及快速原型认证是生存的关键。传统模式下，从用户的一个想法到应用上线，中间可能需要经过环境搭建、框架初始化、代码编写、数据库建模、云端部署上线等一系列复杂繁琐的流程，而本研究提出的“零代码应用生成平台”通过集成智能路由生成方案与一键自动化部署，旨在减少开发者的开发成本，包括时间、技术成本，通过“Prompt即应用”的这种模式，用户不需要关注底层基础设施即可完成应用的生成，极大降低了开发者的开发门槛同时还能提升生产效率。这种技术对于那些有丰富的想法但是由于技术原因不能完成开发的全民开发者显得尤为重要，能够释放其业务创造力而不受技术壁垒的细节束缚。
1.2 国内外研究现状
1.2.1 代码生成与模板化技术研究现状
代码生成是软件工程领域长期研究的经典问题，因为这一技术手段能有效提高开发效率、减少重复性劳动、降低错误的风险。传统的代码生成技术主要依赖于预定义的模板引擎，比如Velocity，一款基于Java的模板引擎，通过特定的语法将Java对象的数据填充到模板中，从而实现界面和Java代码的分离，它的设计意图就是确保Web应用程序在表示层和业务逻辑层之间进行隔离。虽然此类方法能够保证代码结构的严谨性，但是在面对非结构化、多变的业务需求时候就会表现出明显的僵化现象。
近年来，基于Transformer架构的代码大模型成为主流的研究方向。这些模型通过注意力机制捕获代码间的长程依赖，能够生成更具上下文感知能力的逻辑片段‎[3]。当前的趋势是结合检索增强(RAG)技术，将特定领域的API文档或者一些私有代码库作为上下文注入，以解决模型训练数据滞后带来的幻觉问题‎[4]。这种基于学习的方法被广泛应用于代码生成方面的研究，将自然语言描述映射到代码片段、使用抽象语法树辅助生成代码，能自动推断复杂的程序逻辑和结构。最新的研究倾向于结合深度学习模型和传统模板方法，提出混合生成框架以兼顾模板的准确性和学习模型的灵活性，提高代码生成质量‎[5]。
1.2.2 大模型辅助编程与Agent工具调用研究现状
AI编程工具的演进经历了从单点建议转变到工作流改变的过程。现今大语言模型在辅助编程领域的应用十分广泛，国内外很多开发者都会选择一款或多款AI辅助编程工具来为开发提供自动代码补全、错误提示、方案设计以及自动化编码等功能，已经成为提高开发效率和质量的重要工具。例如OpenAI的Codex作为早期生成式AI编程模型，能将用户自然语言指令直接转换成可运行的代码，这得到了许多早期开发者的喜爱。
由于技术的迭代，AI辅助编程模型得到了进一步发展，同期Agent智能体架构逐步成为新一代的辅助编程技术的研究热点。相比传统的LLM单一生成方式不同，Agent能够结合推理规划、工具调用、会话记忆管理等功能，在复杂开发情景下动态调用外部API、执行调试任务以及集成软件流程，从而实现更为自主的编程任务。因此即便没有编程基础，也能构建对话式自动化应用，从而实现大规模代码生成和服务自动化。
学术界针对代码生成Agent的研究也呈爆发式增长。一些研究提出了许多超级智能体系统，用来分解大型代码生成任务并协助完成编码和调试任务，在实验中展现出了极高的效率。总体而言，大模型辅助编程与Agent工具调用正在从简单的代码补全演变为全面自动化开发，AI能结合对上下文的理解和多工具的协同调用能力，为更高效、更低门槛的软件开发提供了新的技术路径。
1.2.3 零代码应用生成产品及学术研究对比分析
零代码应用生成平台作为降低软件开发门槛的技术趋势，在实际应用层面发展迅速。国内外企业以及诸多技术社区都推出了多种零代码AI Agent开发平台。阿里、字节等大厂也推出了基于AI的低代码构建工具，使得无需编程基础的用户也能通过可视化、自然语言描述等方式快速构建出业务自动化或一些有价值的软件产品。部分平台支持通过拖拽组件和自然语言描述结合的方式实现场景级应用构建，其目的是促进业务创新和数字化转型。然而现有的研究和产品在生成的灵活性与部署的自动化之间仍存在断层。许多平台生成的代码难以脱离其特定的封闭环境运行。
从研究角度看，学术界对零代码技术的关注重点主要集中于平台架构、用户交互体验以及与 AI 技术的集成方式等方面。而具体到自动生成产品的质量、可维护性和扩展性等性能指标，研究工作较少深入讨论，多数相关论文侧重于方法框架或示例系统展示。
对比国内外现状，国外的一些成熟产品不仅支持自然语言驱动的自动化生成，还将自动测试、部署等关键环节逐步引入平台闭环中，使产品从构建层面更趋完整。例如熟知的v0产品，能通过自然语言描述或者多模态输入，构建出完整的应用并支持实时预览和修改，使得产品的构建层面更趋完整。国内平台在业务覆盖和行业适配上更贴近本土化应用场景，但在技术深度和 AI 模型集成的精细度方面仍有提升空间。因此研究如何生成标准的、可导出的、且能在通用云环境下快速部署的工程化代码，成为当前软件开发领域的一个重要方向。
1.3 论文主要工作
本论文主要围绕基于Prompt的多类型代码自动生成平台的设计与实现展开研究，并实现如下关键工作：
(1)	设计并实现基于 Prompt 的多类型代码生成模块：通过构建通用 prompt 模板引导大模型输出不同类型的代码，实现能够自动路由生成类型的后端逻辑，覆盖了单文件HTML轻应用、多文件组件化应用和基于Vite构建工具的完整Vue工程项目。
(2)	实现核心模块：后端请求大模型来生成代码，对大模型返回的流式数据进行解析并返回给前端，前端对后端返回的数据做流式渲染，让模型能够边推理边输出结果，用户能立即看到部分效果，减少等待时间，提升用户使用体验。
(3)	管理员后台管理：管理员对系统用户、生成的应用、用户与大模型的聊天消息进行管理。
(4)	实现应用自动化部署能力、封面截图异步生成机制：实现一键部署代码、异步生成应用封面图并上传保存，对静态资源进行托管，提高平台输出成果的易用性和展示效果。
(5)	后端架构构建：集成Mybatis-Plus优化持久层，快速高效地进行数据库操作而无需编写大量SQL脚本，利用Redis实现接口限流和Session管理机制，为后续分布式服务提供可行性。同时利用LangChain4J的声明式服务（AiService）进行大模型能力编排，通过统一的API就能轻松访问各大语言模型。
1.4 论文组织结构
本文围绕“AI零代码应用生成平台”的设计与实现展开，按照从理论到需求、从设计到实现、再到测试验证的思路组织全文，具体结构如下：
第一章 绪论：介绍课题研究背景与意义，梳理国内外研究现状，并概述本文的主要研究内容与创新点，最后给出论文整体结构安排。
第二章 相关技术：对系统实现所涉及的关键技术进行说明，包括零代码/低代码平台的发展概念、前端技术栈（Vue3、TypeScript、Vite）、前端组件与状态管理（Ant Design Vue、Pinia、Vue Router）、后端技术栈（Spring Boot）、ORM 与数据访问（Mybatis-Plus）、缓存与中间件（Redis），以及 Agent 框架与工具调用（LangChain4j）等，为后续章节的系统实现提供技术基础。
第三章 需求分析：结合平台面向个人与小团队的应用场景，从可行性与功能性两个层面展开分析，明确系统角色与功能边界，并通过用例方式对用户端与管理端的核心业务进行抽象。
第四章 系统设计：在需求分析基础上，给出平台的总体业务流程与体系结构设计，说明系统各模块的职责划分与交互关系；随后完成数据库逻辑结构与物理结构设计，给出关键表结构与索引设计思路，为系统实现提供数据层支撑。

第2章 相关技术
2.1 零代码应用生成平台介绍
零代码应用生成平台目前在国内外都有很高的热潮，该项技术代表了软件开发民主化的最高阶段。一个非开发人员，即使没有编程基础，只要拥有创造性思想，即可通过自然语言来构建复杂的应用程序而无需关心具体的开发语言、语法及代码逻辑，实现了网络应用创建的民主化。当然对于专业的开发者来说，零代码或低代码开发也为开发者提供了极大的便利，开发者无需再编写大量的代码，通过大模型提供的海量代码选择并提炼出关键实现代码进行代码重组，从而轻易构建出想要的应用程序。这一方式让程序员的关注重点从以前的代码编写转向业务逻辑本身，加快了软件开发的迭代速度。
生成式人工智能的融入彻底改变了传统开发模式的局限性，当前的零代码平台正转向以意图为中心，让“想法即应用”成为可能性。本此研究设计的AI零代码应用生成平台旨在解决传统开发中环境搭建、学习曲线陡峭、部署流程繁琐等问题。
2.2 前端技术栈
本系统前端开发采用了 Vue 3 框架，其引入的组合式 API（Composition API）为构建AI 对话逻辑提供了极佳的代码组织能力以及平滑的展示效果。TypeScript 的引入不仅在编译阶段捕获了潜在的类型错误，更通过强类型契约确保了前端组件与后端Restful API 之间数据交换的稳定性。构建工具 Vite 凭借其基于原生 ESM 的极速热更新特性，大幅缩短了开发阶段预览的等待时间。
2.2.1 Vue3
前端采用Vue3作为核心开发框架。Vue是一款用于构建用户界面的JavaScript渐进式框架，它基于标准的HTML、CSS和JavaScript构建，并提供了一套声明式的、组件化的编程模型来帮助开发者快速高效地开发用户界面。Vue的两个核心功能便是声明式渲染和响应性。声明式渲染：基于标准的HTML语法拓展了一套模板语法，使得开发者可以声明式地描述最终输出的HTML和JavaScript状态之间的关系。响应性：Vue会自动跟踪JavaScript状态并在其发生变化时响应式地更新DOM元素。它不仅是一个框架，更是一种生态，它的功能覆盖了前端开发者的常见需求，而且设计非常注重灵活性和逐渐集成的特点，也就是由简单到复杂，逐层地添加功能，而不需要从一开始就全盘地接受整个庞大的框架，框架的概念图如图2- 1 Vue渐进式框架概念图所示：

图2- 1 Vue渐进式框架概念图
Vue目前有两个版本可用：Vue2和Vue3。相比于Vue2的选项式API（Options API），其包含多个选项的对象来描述组件的逻辑，例如data()返回的属性将会成为响应式的状态并且暴露在this上，于是在模板中就可以使用data暴露出来的数据进行后续的数据处理； mounted作为生命周期钩子来使用，它会在组件生命周期的各个不同阶段被调用，比如当页面首次加载时尝试获取登录用户信息。而Vue3在保持Vue理念的同时，提供了更好的性能、更强大的类型支持（Map、Set等）和更灵活地代码组织方式。Vue3优先推荐选用组合式API（Composition API），能为构建复杂的AI对话逻辑提供更优的代码组织模式，更好地实现逻辑复用，其轻量级的虚拟DOM和高效的响应式系统，在处理AI流式响应和状态同步时表现得更为卓越。
在零代码应用生成平台上，用户与AI的交互不再是简单的对话，而是实时的、可见的构建过程，从代码流式输出到工具调用结果显示，让用户以可控的方式让AI来辅助完成整个应用程序的构建。
2.2.2 TypeScript
TypeScript是微软在2012年推出的一门开源、跨平台、渐进式的编程语言，它在语法层面是JavaScript的超集。它并不是取代JS，而是在JS的基础上，提供了更多的基本数据类型、接口和枚举等，通过类型推断加上结构化类型让开发者写少量的注解就能拿到大量类型安全。任何合法的.js文件直接改成.ts后缀就能编译通过，因此在开发阶段，开发者可以逐步加上类型注解和面向对象/泛型等高级特性，但是类型只在编译阶段存在，在运行阶段会被完全消除，这是一种零运行时开销的方式，并且代码在编译阶段就能发现错误，最终才被编译成干净的、可运行在JS引擎上的普通JavaScript。
本次设计中引入TypeScript不仅为了在编译阶段捕获潜在的类型错误，更通过强类型契约确保前端组件在与后端Restful风格的API进行数据交换时产生的数据类型不一致问题，通过定义了一系列与后端API交互的实体，简化前端开发时进行数据处理的复杂性。
2.2.3 Vite
在浏览器支持ES模块之前，JavaScript并没有提供原生机制让开发者以模块化的方式进行开发，因此开发者急需一种工具来抓取、处理并将源码模块串联成可以在浏览器中运行的文件。过去使用webpack等工具来打包构建客户端代码很方便，但随着构建项目越来越大，需要处理的JavaScript代码数量也呈指数级增长，因此基于JS开发的这些工具就会遇到性能瓶颈问题：通常需要很长时间才能启动开发服务器，并且在运行阶段，代码文件被修改之后也需要几分钟才能在浏览器中反映出来修改之后的效果，这种迟钝的反馈极大影响了开发者的开发效率和体验‎[6]，对应的工作流图如图2- 2传统打包方式工作流图所示

图2- 2传统打包方式工作流图
这种打包方式所有源码与依赖必须先由 Webpack/Bundler 打包成一份完整的 bundle，服务器才能启动；bundle 结束后整个应用一次性就绪，这种方式伴随而来的问题是项目越大，首次 bundle 时间越长。
Vite旨在利用生态系统中的新进展来解决上述问题，目前浏览器开始支持ES模块，且越来越多的JavaScript工具使用编译型语言来编写。Vite通过在一开始就将项目中的模块区分为两类：依赖和源码，只需要在浏览器请求源码时进行转换并按需提供源码，根据情景动态导入代码，也就是在屏幕上实际使用时候才会进行这种转换操作，极大改进了开发服务器的启动时间，对应的工作流图如图2- 3 Vite打包方式工作流图所示：

图2- 3 Vite打包方式工作流图
在这种打包方式下服务器启动时只做依赖预构建，把裸 ESM不规范的依赖转译成真正 ESM 并做缓存，源码文件保持原生 ESM 形态按需提供。浏览器请求哪个路由，Vite 就及时转换并提供对应模块，而未访问的模块不做任何处理。这种方式下冷启动只跟“依赖数量”有关，几乎不随业务代码量增长而变慢，从而让实现毫秒级冷启动与秒级热更新成为可能。因此本次选择Vite作为前端构建工具来进行开发，就是凭借其基于原生ESM的急速热更新特性，大幅缩减开发预览的等待时间，加快前端开发速度。
2.3 前端组件与状态管理
2.3.1 Ant Design Vue
Ant Design作为一门设计语言，自问世以来经历过多年的迭代和积累，它对UI的设计思想已经成为一套事实标准。Ant Design很注重一致性、可复用性和信息表达的清晰性，能够在保证前端页面展示的美观性的同时兼顾开发者的开发效率，适合快速高效地开发出美观的前端或者后台管理系统。
Ant Design Vue则是Ant Design在Vue技术栈下的实现，组件风格和设计规范与Ant Design保持同步，而且组件的HTML结构和CSS也保持一致，这种一致性显著降低了前端的开发成本，同时也助力开发者在不同技术栈之间的迁移和复用开发经验。
在本系统中，Ant Design Vue 主要用于构建前端展示页面和后台管理界面中的交互组件，例如对表单输入与验证、弹窗提示、数据表格的美观展示、分页组件及布局结构等。通过使用其丰富的现成组件，显著减少了大量重复性的 UI 编码工作，在提高整体开发效率的同时保证界面的稳定性。同时，Ant Design Vue 对 TypeScript 和 Vue3d的组合式 API 提供了良好支持，有利于后续系统的维护和扩展。
2.3.2 Pinia
Pinia是Vue的专属状态管理库，支持服务端渲染，Pinia允许我们跨组件或者页面来共享某个全局状态。相较于 Vuex，其 API 更加简洁，语义更清晰，并且与 Vue 3 的组合式 API 深度融合。 Pinia 以 Store 为核心单位，将系统中的不同业务状态划分为独立模块来进行管理。每个 Store 既可以定义自身的状态数据，也可以封装对应的业务逻辑和异步操作，从而实现状态与行为的统一管理。这种设计方式有效降低了不同业务模块之间的耦合度，提升了代码的可维护性和可扩展性，而且搭配TypeScript一起使用能提供非常可靠的类型判断支持。
随着系统功能的不断扩展，前端组件之间需要共享的状态信息逐渐增多，例如已登录的用户信息应该全局共享，因为在除了首页、登录和注册之外的每一个页面都会用到已经登录的用户信息，用来在进入某个页面之前判断用户是否已经登录，方便后续前端请求后端接口然后返回数据、处理数据并展示，同时展示顶部的头像昵称等信息。因此为解决多组件状态共享和数据一致性问题，本系统采用 Pinia 作为全局状态管理方案。
通过 Pinia 的集中式状态管理机制，系统不但避免了复杂的父子组件之间的数据传递问题，而且提高了数据流的可追踪性和代码的可维护性。
2.3.3 Vue Router
Vue Router 是 Vue 官方提供的前端路由管理工具，能实现页面级组件的动态加载与切换，是用来构建单页面应用的核心组件之一。客户端路由的作用是在单页面应用中将浏览器中的URL地址与用户看到的页面绑定起来，当用户尝试访问不同的页面时，URL会随之更新，但页面不需要从服务器重新加载。本系统也是采用 Vue Router 来对前端页面进行统一的路由规划和重定向等操作。
在系统结构设计中，前端页面主要包括用户登录注册模块、忘记密码找回密码模块、对话页面模块、应用详情等功能模块，后台管理中的用户管理、应用管理以及对话管理模块。通过 Vue Router 的路由映射机制，将不同的 URL 路径与对应的组件绑定起来，实现前端页面上的逻辑解耦。
此外，本系统结合 Vue Router 提供的路由守卫机制，实现了基于用户登录状态和权限信息的访问控制策略。当用户未通过身份认证或权限不足时，系统将自动拦截路由跳转并进行重定向处理，确保后台管理页面只有管理员才能访问，从而在前端层面增强系统的安全性与健壮性。
2.4 后端技术栈
Spring Boot是Pivotal团队推出的一款用来快速进行Java开发的框架，用来简化Spring应用的初始搭建与开发过程。它并不是要取代Spring，而是把Spring封装进一个开箱即用的盒子里面，让开发者能够专注于业务逻辑而不是进行复杂繁琐的配置。
本系统后端采用 Java 语言作为开发语言，并基于 Spring Boot 框架构建整体服务架构。Spring Boot 通过约定优于配置的设计思想，显著降低了传统 Spring 项目在配置层面的复杂度，比如在Spring中需要使用大量的XML文件来配置bean，而且要手动管理各个依赖的版本，有较高的学习难度和技术复杂性。而Spring Boot提供的自动装配以及starter依赖，学习和上手较为容易，在大幅简化配置的同时使开发者能够更加高效地完成业务功能的开发。
Spring Boot 内置Tomcat服务器，并对常见中间件和第三方组件提供自动化配置支持，非常适合构建 Restful 风格的 Web 服务。在本系统中，Spring Boot 主要负责对外提供统一的接口服务，协调各业务模块的逻辑处理，同时作为系统与数据库、缓存及 AI Agent 模块之间的核心枢纽。此外，Spring Boot 还具备良好的扩展性和生态兼容性，能够方便地集成 Mybatis-Plus、Redis 以及 LangChain4j 等组件，为本次系统整体架构的稳定运行和后续功能扩展奠定了良好的基础。
2.5 ORM与数据访问
在系统数据访问层设计中，为了兼顾开发效率以及数据库操作的灵活性，本系统选用 Mybatis-Plus 作为 ORM 框架。Mybatis-Plus 是在 Mybatis 框架基础上的增强工具。Mybatis作为一款半自动ORM框架，其SQL与Java代码分离，SQL封装在XML文件中或者通过在方法上通过注解SQL的方式来访问数据库，只提供了基础的增删改查模板和结果映射，同时具备零侵入性，因为不强制继承任何类或者实现任何接口。而Mybatis-Plus 在Mybatis的基础上进行了增强但是不修改原有逻辑，提供了通用 Mapper 接口、条件构造器以及自动分页等功能，使开发者在无需编写大量 SQL 语句的情况下即可完成常见的数据库操作。同时，对于复杂查询和一些特定业务场景，仍可通过自定义 SQL 方式进行灵活的扩展。
在本系统中，Mybatis-Plus主要承担用户数据、应用信息、生成记录及对话历史等结构化数据的持久化任务，通过其提供的 IService 与 QueryWrapper，系统能够以近乎零 SQL 的方式完成基础的增删改查操作，极大地加快了业务逻辑的迭代速度。同时，MyBatis-Plus 对逻辑删除以及自动字段填充特性的支持，为系统的安全性与数据完整性提供了一套开箱即用的解决方案，显著提升了数据访问层的开发效率，并增强了系统的可维护性。
2.6 缓存与中间件
Redis通常被称为数据结构服务器，因为其值（Value）可以存储字符串（String）、哈希（Map）、列表（list）、集合（Set）等类型。Redis采用C语言进行开发，采用内存存储方式，具有读写速度快、支持多种数据结构等特点，适合用于缓存热点数据和短期状态信，以致于Redis在多方面发挥着重要的作用，是互联网技术中使用最为广泛的中间件之一。
Redis 在本系统中承担了多方面的职责。首先利用其高性能的键值存储实现分布式会话管理，在用户登录成功之后将Token以及Session存储在Redis中，在后续请求的时候携带Token即可请求服务器资源。除了分布式会话管理，Redis还作为接口限流器（Rate Limiter）来使用，用户访问需要被限流的接口时，生成唯一的接口限流Key并设置每个时间窗口允许的请求数，同时关联用户，将其保存到Redis，防止恶意刷取 AI Token 造成成本失控。
本系统引入 Redis 作为缓存与中间件组件，提高了系统响应速度和并发处理能力。通过合理引入 Redis 缓存机制，系统有效降低了数据库访问频率从而给数据库减压，提高了整体性能和稳定性。
2.7 Agent 框架与工具调用
LangChain4j 是 Java 生态中较为先进的生成式 AI 集成框架。LangChain4j提供了统一的API就能对接各类LLM提供商，使开发者无需为每个服务单独学习和实现其API，因此在尝试不同的LLM时可以轻松进行切换，无需重写代码。它不仅仅是简单的 API 包装器，更是一个提供统一抽象、类型安全等功能的集成平台。LangChain4j的目标便是简化在 Java 应用中集成大语言模型（LLM）的过程‎[7]。
本系统深度利用了 LangChain4j 的以下核心特性：声明式 AI 服务 (@AiService)：使用 @AiService 注解可以定义一个 AI 服务，而 @SystemMessage 和 @UserMessage 则分别用于设定代理的内置Prompt和用户传来的消息。通过接口定义与注解，系统可以优雅地隔离 AI 逻辑与业务逻辑，框架会自动处理 Token 映射与模型交互的细节；函数调用与工具集成 (@Tool)：系统为 LLM 提供了一套预定义的工具箱，例如 FileDirReadTool等，这使得智能体能够自主检索项目目录结构，从而实现具有上下文感知能力的代码修改建议；响应式流式输出 (Flux)：由于LLM 是逐个 token 生成文本的，因此许多 LLM 提供商提供了流式传输响应的方式，即逐个 token 地返回结果，而不是等待整个文本生成完成。这种方式可以显著改善用户体验，因为用户不需要等待一个未知时长，几乎可以立即开始阅读大模型返回的消息。
本系统引入LangChain4j框架，实现了从被动文本生转向主动任务执行，显著提升了平台的智能化水平和实际应用价值。

3.1.1 经济可行性
考虑到经济可行性，本系统前后端均采用开源技术体系进行开发，系统核心框架和组件均为开源软件，包括 Spring Boot、Vue3、Mybatis-Plus、Redis 以及 LangChain4j 等，均无需支付高昂的商业授权费用即可进行高效开发，有效降低了软件的开发成本。
平台支持部署在云服务器或本地服务器环境中，对硬件资源要求相对较低。本次开发先在本地进行全面开发，本地开发结束并确保系统可运行以及安全的情况下，部署到云服务器提供公网访问使用。在用户实际运行过程中，管理员可根据系统访问量和业务规模灵活调整服务器配置，避免一次性高投入。本系统采用前后端分离架构，前端通过静态资源方式部署，后端服务独立维护扩展，有利于控制运维成本。在算力支持方面，系统通过对接第三方主流大模型（ DeepSeek、阿里百炼大模型）的 API 接口，采用灵活的按量计费模式，相较于自行购置并维护高性能 GPU 集群，极大降低了初始资本投入和运营成本，具备良好的经济可行性。
3.1.2 技术可行性
当前主流的B/S架构整体采用前后端分离模式，本系统中前端Vue3开发框架及其配套生态（Ant Design Vue、Pinia、Vue Router等）都是当前主流的前端技术方案，具有良好的社区支持和稳定性，能够满足复杂交互界面以及状态管理等需求。后端则基于 Spring Boot 构建 Restful风格的 API接口，两者之间通过 HTTP 通信来进行数据交换，系统架构清晰、职责明确。Spring Boot 框架拥有完善的生态体系和广泛的应用实践，能够支撑高并发访问以及模块化开发需求。Mybatis-Plus 作为 ORM 框架，简化了数据访问层的实现，提高了开发效率。Redis 的引入为系统提供了缓存、限流及会话管理能力，系统的性能扩展和高并发场景得到了技术支撑。当前大模型的代码生成能力已经趋于成熟，能够稳定生成符合语法规范并且满足可运行、效果美观等需求的 Web 代码。本系统采用 LangChain4j 框架集成AI代码生成并对大语言模型进行统一封装，使模型调用和工具调用逻辑具备良好的扩展性和可维护性。事实证明无论从技术实现还是从扩展能力角度来看，本系统都具备良好的技术可行性。

3.2 功能需求
3.2.1 系统角色分析
根据系统设计目标和实际使用场景，本次开发的AI零代码应用生成平台主要面向普通用户和系统管理员两类人群。因此，系统设计了两个角色：普通用户user和管理员admin。在系统中，普通用户是系统的主要使用者，考虑到不同用户群体的特点和技术熟练度，系统依据用户是否注册，将用户分为游客和已注册登录用户。游客能看到管理员配置的精选应用并进行访问，已注册登录用户在登录成功之后可以通过初始提示词（initPrompt）来创建应用，创建成功之后能实时看到代码的流式输出，待全部输出完成之后系统会自动构建应用并展示给用户，用户后续可以继续与AI对话来完善项目。当生成到用户满意的时候，可以点击部署来让系统完成自动部署并返回可在线访问的链接。而系统管理员在成功登录到后台页面之可以对系统中的用户、应用和所有聊天消息进行管理。通过在前端以及后端都设置了不同的访问权限以及访问功能，确保平台的安全性和规范性，以保障系统的有序运行。
系统主要服务于两类用户群体：
1.	普通用户 (User)：应用创作者，利用 AI 编写代码并进行在线预览与部署。
2.	管理员 (Admin)：系统运营者，负责监控平台流量、审核违规内容、管理用户状态及配置全局生成策略。
3.2.2 用户功能分析
系统的用户功能主要用来满足其注册登录、生成应用、修改应用、部署应用、下载应用代码和查看系统中的精选作品需求。
游客在访问系统时，系统提供了注册登录和基本的访问管理员已经设置的精选作品功能，当游客完成注册登录之后，可以在系统中完成应用创建、AI 对话生成以及应用部署等操作，其功能需求主要包括以下几个方面：
	1.	用户注册与登录功能
系统应支持用户注册与登录功能，用户注册后可通过账号密码登录系统，并维护个人基本信息。用户信息存储于 user 表中，包括头像链接、个人简介、邮箱、性别等字段，用于展示用户资料和进行个性化服务。
	2.	应用创建与管理功能
用户可在系统中创建应用，并对已有应用进行管理。应用信息存储于 app 表中，主要字段包括应用名称（appName）、应用封面（cover）、初始 Prompt（initPrompt）、代码生成类型（codeGenType）以及部署标识（deployKey）等。用户可对应用进行编辑、查看和删除等操作。
	3.	AI 对话生成代码与历史记录管理
系统支持用户通过自然语言与 AI 进行对话，生成对应的代码或应用配置。每次对话过程和生成结果将被记录至 chat_history 表中，主要字段包括消息内容（message）、消息类型（messageType）以及所属应用 ID（appId），便于用户后续查看和追溯生成历史。
	4.	应用部署与访问功能
用户在完成应用生成后，可通过系统提供的一键部署功能将应用部署至云端并支持在线访问。系统通过 deployKey 标识部署实例，并记录应用的部署时间（deployedTime），为后续访问和运维提供依据。
3.2.3 管理员功能分析
- 用户管理（角色、信息维护、封禁/删除逻辑可基于 isDelete 扩展描述）
- 应用管理（优先级 priority、应用审核/排序等）
- 对话/内容管理（历史记录审查、敏感内容治理等）

4.1 系统任务流程图
系统核心任务可概括为两条主流程：其一是“AI 生成代码流程”，侧重于从自然语言到代码产物的生成、解析与保存；其二是“应用部署流程”，侧重于将生成结果快速发布并对外提供访问能力。两条流程既可以独立使用，也可以串联形成“生成—预览—部署”的闭环。
4.1.1 AI 生成代码流程
AI 生成代码流程以“应用（App）”为载体展开。用户首先创建应用并进入对话页面，然后通过自然语言描述需求，系统将对用户意图进行识别并选择对应的代码生成类型，最终把生成产物保存到数据库并在前端实时展示。具体步骤如下：
(1)	用户输入需求：用户在对话框中输入功能描述，例如“生成一个响应式的个人简历网页”“生成一个表单页面并带校验逻辑”等。
(2)	生成类型路由：后端根据用户输入及应用配置，选择对应的生成类型：
	HTML - 适合简单的静态页面，单个 HTML 文件，包含内联 CSS 和 JS。
	MULTI_FILE - 适合简单的多文件静态页面，分离 HTML、CSS、JS 代码。
	VUE_PROJECT - 适合复杂的现代化前端项目。
该步骤的目标是让不同类型需求走向不同 Prompt 模板与解析策略，提升输出稳定性。
(3)	Prompt 构造：系统将用户需求、应用上下文（历史消息、生成配置）与预制的 System Prompt 拼接，形成最终请求大模型的提示词。
(4)	LLM 生成与工具调用：通过 LangChain4j 调用大模型完成内容生成；当生成过程中需要读取模板、写入文件结构、进行目录遍历等操作时，由工具调用能力（Tool）承担具体执行，并把工具结果回填到对话上下文中。
(5)	流式输出与前端渲染：后端采用流式响应方式将生成内容逐段返回，前端对流式数据进行实时渲染，使用户能够“边生成、边看到”，同时在交互体验上减少等待感。
(6)	结果解析与落库保存：系统将生成内容解析为平台内部标准格式（代码正文、文件结构、运行说明等），并写入应用表/历史表，形成可追溯记录。
(7)	异常处理与重试：当模型输出不符合格式或出现网络/限流等异常时，系统返回可读的错误信息，并允许用户在同一应用下重新发起生成。
该流程的设计重点在于“可控”。通过路由策略与预制 Prompt 约束输出格式，通过工具调用把不可控的“编造文件/编造目录”变为可验证的“实际读取/实际写入”，从而提升生成结果的工程可用性。AI生成代码流程如图4- 2所示：

4.1.2 应用部署流程
应用部署流程以“快速可访问”为目标，面向个人或小团队的真实使用场景。流程如下：
(1)	生成完成与产物校验：用户在对话中获得代码后，可选择预览或直接部署。系统对生成产物进行基础校验（如是否包含入口文件、是否满足部署类型要求）。
(2)	生成部署标识 deployKey：系统为每次部署生成唯一的 deployKey，用于标识部署实例及对外访问地址，同时避免应用名冲突。
(3)	发布与静态资源托管：对于可直接构建部署的前端产物，系统执行构建/上传，将静态资源托管到系统目录中。当用户通过URL来访问生成的应用时，后端根据URL选择性返回具体的文件资源以便前端用户能直接在浏览器看到生成的应用效果。
(4)	更新部署状态：部署成功后更新 app 表的部署字段（deployKey、deployedTime），便于在查看应用详情的时候能直接看到应用部署标识和部署时间。
(5)	用户访问：用户通过平台提供的访问链接打开已部署应用，实现“从需求到上线”的闭环体验。
在部署链路中，系统强调“可追踪”。deployKey 与 deployedTime 等字段可以帮助管理员定位发布批次，实现故障回溯与问题定位。应用部署流程如图4- 3所示：

4.2 系统体系架构
本系统采用典型的 B/S 架构与前后端分离模式，整体由用户端前台、管理员端后台与后端服务三部分组成，并以 MySQL+Redis 提供数据支撑，以 LangChain4j 作为 AI 能力接入层。系统总体架构可划分为以下四层：
(1)	表现层（Presentation Layer）
表现层包含两套前端：
1)	用户端前台（ai-code-front）：提供注册登录、应用创建、AI 对话生成、生成结果预览、应用部署与个人中心等功能。
2)	管理端后台（ai-code-front-admin）：提供用户管理、应用管理、对话/内容管理等运维能力。
前端整体采用 Vue3 + TypeScript + Vite 构建，使用 Ant Design Vue 提供统一的交互组件，并通过 Pinia 进行全局状态管理，Vue Router 实现路由与权限控制。
(2)	业务层（Business Layer）
业务层以 Spring Boot 为核心，按 Controller / Service / Mapper 分层组织：
1)	Controller 层：对外提供 Restful API，负责参数校验、鉴权与请求编排。
2)	Service 层：承载业务逻辑，包括应用创建、对话生成编排、部署触发、封面截图异步任务调度等。
3)	Mapper/DAO 层：基于 Mybatis-Plus 对数据库进行增删改查操作，提升开发效率并减少重复 SQL 编写。
(3)	数据层（Data Layer）
数据层由 MySQL 与 Redis 组成：
1)	MySQL：存储用户信息、应用元数据、对话历史、部署状态等结构化数据，保证数据一致性与可持久化。
2)	Redis：用于会话/Token 管理、接口限流、热点数据缓存等，提高系统抗并发能力与整体响应速度。
(4)	AI 生成层（AI Generation Layer）
AI 生成层由 Prompt 模板、路由策略与 LangChain4j 工具调用组成：
1)	Prompt 模板：针对不同生成类型维护预制 System Prompt，明确输出格式、代码边界与注意事项。
2)	路由策略：根据用户需求/应用类型选择 Prompt 与解析器，保证不同生成任务走不同链路。
3)	工具调用（Tools）：把“读取目录、写入文件、解析结构”等能力以工具形式提供，模型通过函数调用方式触发工具执行，工具结果回流到模型上下文，减少幻觉并提高可用性。
通过上述分层，系统实现了前端交互、业务编排、数据持久化与 AI 生成能力的解耦，使平台在后续迭代中更容易扩展新的生成类型、部署方式或管理能力。系统体系架构图如图4- 4所示：

4.3 数据库设计
数据库是平台稳定运行的核心基础。本系统属于典型的“用户—应用—对话—部署—统计—配置”类平台：既要存储用户信息与权限，又要记录应用元数据、生成对话历史，同时还包含每日访问统计、AI 模型配置、邮件配置等运维的相关数据。因此数据库设计目标主要包括：①实体关系清晰、数据归属明确；②关键字段具备唯一约束与必要索引，保证高频查询性能；③保留软删除与时间戳字段，便于审计与回溯。
4.3.1 数据库逻辑结构设计
结合系统业务流程与功能模块，平台核心数据实体如下：
(1)	用户（user）
用于保存用户的账号体系与基础资料，同时记录注册/登录行为信息。用户表是平台鉴权与资源归属的基础，后续 app、chat_history 等表均通过 userId 与其建立关联。
(2)	应用（app）
用于保存用户创建的应用元数据、生成类型与部署状态。应用表通过 userId 与用户建立归属关系，通过 deployKey 标识一次部署实例，并通过 priority 支持精选排序等运营功能。
(3)	对话历史（chat_history）
用于记录用户与 AI 的每次交互，包含消息内容 message、消息类型 messageType（user/ai）、所属 appId 与 userId。该表是“可追溯”的关键：既方便用户查看生成历史，也方便管理员审查内容与排查问题。
(4)	每日访问统计（view）
用于按天统计平台访问量，dateStr（yyyy-MM-dd）保证每天一条记录，便于后续展示运营数据与容量评估。
(5)	AI 模型配置（ai_model_config）
用于保存平台接入模型的配置项（baseUrl、apiKey、modelName、maxTokens、temperature、maxRetries 等），通过 configKey 区分不同用途的模型（流式对话模型、推理模型、路由模型）。该设计使模型供应商或参数调整不需要改代码，提升可运维性。
(6)	邮件配置（email_config）
用于保存 SMTP 配置，支撑找回密码涉及到的邮件能力，避免将敏感配置硬编码到代码中。
从实体关系上看：user 与 app 为一对多关系；app 与 chat_history 为一对多关系；chat_history 同时持有 userId 与 appId，便于按用户维度或按应用维度检索。

4.3.2 数据库物理结构设计
本系统数据库采用 MySQL，字符集统一使用 utf8mb4_unicode_ci，以保证对中文及表情符号等内容的良好支持。各表统一包含 createTime、updateTime 字段，结合 isDelete 软删除字段，满足数据审计与回滚需求。

致 谢
2021年自小县城考入扬州大学，第一次认识了班主任也是我后来的导师杨凯老师，大一高数期中考试考完杨凯老师和我说“果然没看错你”让我记忆至今，后来我一直想要对得起杨老师的信任。自22年跟着杨老师开始做科研，学习图机器学习，参加比赛，那时还懵懵懂懂不知道未来的路。23年12月份大三下，继续跟随杨老师做项目，在此期间寒假留校，年后去公司验收，一直到24年5月份逐步收尾。在此期间和杨凯老师有过许多关于未来的交流，以及对项目的感受，适逢大模型潮流，在研究AGI后让我似乎确立了未来的方向，遂决定静下心来考研。暑假留校专心考研，自六月底至考研前，日均学习11个小时，期间无数次怀疑自己，期间很感谢我的女朋友王妍以及我的家人，朋友。由于备考时间紧张，我几乎没有时间去到女朋友的校区陪她，期间均是她来陪我，不断安慰鼓励我。备考时间短，11408任务量大再加上基础薄弱，至25年考研成绩出来后，距离目标院校的分数还是差了一些，遂准备调剂。看了一个月后，还是不甘心，想要二战。四月份，收到了杨凯老师的电话：“小封，要不要跟着我。”我既惊喜又慌张，我非常想要对得起杨老师给我的这份信任，但由于我自己选择的未来方向，我只能向杨凯老师表明我的想法，决定二战。杨凯老师也十分支持我，恩情莫过知遇，感戴莫名。在家人朋友的支持下，我决定开始二战，便尽早完成了这篇论文。
回顾我的大学四年，我从来不曾优秀过，自大二开始，便没有过完一个完整的寒暑假，大二暑假提前来做比赛，大三寒假做项目，暑假留校考研，大四寒假毕业实习，但又好像都碌碌无所得‎[1]，科研没有做出什么成果，考研也失利。迄今为止，可以说我的大学四年是失败的，于我而言，只能继续走下去，只剩下一句不要把梦想埋没。
感谢那些曾经帮助我的人，特别是杨凯老师；谢谢梅士坤老师、王浩月老师、吴潇雪老师、孙念心老师、以及信工部的老师们，我会用努力对得起大家的信任，谢谢你们的关心和照顾。
